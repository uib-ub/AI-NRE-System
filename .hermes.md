# AI-NER-System Hermes Instructions

You are assisting with the AI-NER-System project.

## Project boundaries

- Work only inside this repository.
- Do not access production servers.
- Do not use UiB credentials, SSH keys, certificates, tokens, or private datasets.
- Do not call external paid APIs unless explicitly instructed.
- Use synthetic or tiny sanitized sample texts for tests.
- Prefer small, reviewable changes.
- Do not rewrite large parts of the codebase without first producing a plan.
- Do not modify `.env`, real credentials, SSH configuration, or system-level files.

## Branch workflow

- Do not work directly on `testing`, `master`, or `main`.
- Use `testing` as the base branch for normal development.
- Create a small task branch for each task, for example:
  - `test/main-cli-coverage`
  - `docs/testing-baseline`
  - `fix/docker-permission-tests`
- Keep each branch focused on one task.

## Development workflow

1. Inspect the relevant files.
2. Propose a small plan.
3. Make minimal changes.
4. Run tests.
5. Show the git diff.
6. Summarize what changed, what was verified, and what remains risky.

## Testing expectations

- Prefer pytest.
- Add or update tests before refactoring.
- Keep fixtures small.
- Do not commit sensitive/private text.
- Use English for repo files and documentation.
- Personal planning documents may be Chinese-English mixed, but real repo documentation should use English.
- Run the Docker test command as the host UID/GID, not root.
- Do not treat root-container permission-test failures as product failures without verifying with host UID/GID.

## Docker test baseline

The preferred test workflow is:

```bash
./scripts/test-docker-host-user.sh
```

If the script is not available, use:

```bash
docker run --rm \
  --user "$(id -u):$(id -g)" \
  -e HOME=/tmp \
